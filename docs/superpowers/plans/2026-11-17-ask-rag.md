# `ask` Command Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A visitor types `ask <question>` in the burnsOS terminal and gets a short, cited answer about Dylan and the portfolio's work, produced by a deterministic pipeline around exactly one model call.

**Architecture:** Pure TypeScript modules in `src/lib/ask/` (corpus, text, intent, retrieve, validate, pipeline) with no network access, wrapped by one route handler (`POST /api/ask`) that adds transport guards and the real model provider. The static terminal (`public/burnsos.html`) calls the route. A golden set drives deterministic tests in the normal gate and a separate live-model eval script.

**Tech Stack:** Next.js 16 App Router route handler (Node runtime), TypeScript, Vitest, Playwright, Vercel AI SDK through Vercel AI Gateway (`anthropic/claude-haiku-5.5`).

**Spec:** `docs/superpowers/specs/2026-11-17-ask-rag-design.md`. Read it first; this plan argues from it.

> **Amended after Task 11 (live eval).** Where this plan says "AI Gateway" and "temperature 0", the shipped
> code differs: with `ANTHROPIC_API_KEY` set the route uses the direct Anthropic provider (`claude-haiku-5-5`)
> and the AI Gateway budget does not apply (a dedicated Anthropic workspace key with a spend limit is
> required instead); without it, AI Gateway as planned. No temperature is sent on either path (the 5.5 models
> reject it), so answer wording is not deterministic; repeats come only from the per-instance cache. A
> per-instance daily model-call ceiling (500 per UTC day) was added. The spec is current; this plan is not
> rewritten.

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before writing Next.js code (`AGENTS.md`). After installing the AI SDK, read `node_modules/ai/docs/` for the structured-output call; do not rely on remembered APIs.
- Scope is "who I am and the work I have in the portfolio". Employers, location and availability are deflected, never answered.
- Exactly one model call per answered question; zero for `deflect`, `meta`, `refuse`, below-floor retrieval, cache hits and the `off` state.
- A failed validation never retries the model.
- The server returns plain text; the terminal inserts it with `textContent`, never `innerHTML`.
- Never recite an email address or URL in an answer.
- Role and period for `remoteretros`, `syene` and `keel` are unconfirmed (`TODO(owner)`) and are held out of the corpus.
- No new shared store. Abuse control is: a Vercel Firewall rate-limit rule on `/api/ask`, an AI Gateway spend cap of $5 per month, and an in-memory per-instance limiter as a second layer. (This narrows the spec's "shared store" option; update the spec's Security and "Needed from the owner" sections to match in Task 9.)
- Store no question text. Log counts by reply kind only.
- The feature is off unless `ASK_ENABLED === "1"`.
- Existing gate stays green: `npx tsc --noEmit && npm run lint && npm test && npm run build && npm run test:e2e` (delete `.next/types` first if a route was added or removed).
- Commit after every task. Do not push; the owner decides when it goes live.

## Review Focus

1. **Blank or symbol-only question** (`""`, `"   "`, `"???"`, emoji only): a `refuse` reply, no model call. Pinned in Task 2 and Task 7.
2. **A question naming two projects** ("how do Keel and Syene differ?"): passages from both reach the model. Pinned in Task 4.
3. **The provider throws or times out:** a `busy` reply, HTTP 200, no retry, no stack trace. Pinned in Task 7 and Task 9.
4. **The model cites an ID it was not given, or returns an invented number:** the visitor sees the extractive fallback, not the model's text. Pinned in Task 6 and Task 7.
5. **The same question with different case, spacing or trailing punctuation:** identical reply and only one model call in total. Pinned in Task 7.
